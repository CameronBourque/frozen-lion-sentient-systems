# Risks

What could go wrong, what it would cost, and the fallback. Open questions that a test can answer live in [findings/](findings/README.md), and the rows below link to them. See [rules/docs.md](rules/docs.md#risks).

| Risk | Impact | Fallback or mitigation | Tracked in |
| --- | --- | --- | --- |
| The FireTuner protocol is undocumented, slow, or unstable | The whole bridge depends on it | Proven in single player in [phase 0](roadmap/phase-0/README.md). The bridge lists cities, moves a unit, and gets the turn signal within about a second, and the released executable passes the same checks. Once, the game stopped listening on 4318 after a long session, so that question stays open. If the tuner fails later, a hook DLL, found through reverse engineering, adds a native socket | [tuner-protocol.md](findings/tuner-protocol.md#results), [game-api.md](findings/game-api.md#results), [build-tooling.md](findings/build-tooling.md#results) |
| The bridge's state list goes stale while the tuner stays connected | After a quit to the main menu, the socket stays open and `InGame` is gone. A later load may move states to new indexes. Commands then fail or run in the wrong state | The core mod reports each load, so the bridge lists the states again. Each command checks its state with `ContextPtr:GetID()`. On `ERR:Invalid Lua State`, the bridge lists the states again | [lua-contexts.md](findings/lua-contexts.md#state-list-over-a-session), question 2 |
| The tuner closes in hotseat | Agents can't act in a hotseat game, so you can't play alongside agents | Phase 0 and the MVP stay single player. A later test puts an agent in a computer slot with the native AI held back. See [slot-type.md](design/agents/slot-type.md#computer-slot-test). Backups: live reload of a UI Lua file for input with `Lua.log` for output, then a hook DLL | [multiplayer.md](findings/multiplayer.md#hotseat) |
| The tuner closes in online games | Advisors can't read your state through the tuner in an online game | Advisors start in single player. The core mod still runs online and its prints reach `Lua.log`, so a read-only channel through the log may work. See [advisors.md](design/advisors.md#open-questions). Backup: a hook DLL | [multiplayer.md](findings/multiplayer.md#online) |
| Game state is large | Too much state makes turns slow and expensive | Measure, then trim. Facts go through `lookup` | [testing.md](design/testing.md#state-size), [phase 1](roadmap/phase-1/README.md) |
| Agent turns may run one after another | Several agents can make you wait minutes between your turns | Handle trivial actions in plain code, run fewer deep reviews, and use smaller models where tests allow | [turn-loop.md](design/agents/turn-loop.md) |
| No sweat is hard to steer | Models default to reasonable play | Tune from logs, decision records, and playtests | [sweat-level.md](design/agents/sweat-level.md) |
| Some map-reveal mods change game data | A reveal could leak information to an agent | Pick a rendering-only reveal and test it | [cover-and-spectator.md](design/agents/cover-and-spectator.md#map-reveal), [phase 4](roadmap/phase-4/README.md) |
| The game property API may not be writable from the needed Lua state | Checkpoint IDs depend on it | None yet | [game-api.md](findings/game-api.md#game-properties-for-checkpoint-ids), question 1 |
| UI Lua may not be able to dismiss the hotseat pass screen | If games with you and agents use hotseat, agent turns must start without a click | None yet | [game-api.md](findings/game-api.md#questions), question 2 |
| macOS and Linux builds are untested | They decide which platforms ship | Ship Windows only until each platform passes the phase 0 gate on a real machine. macOS also needs signing and notarization, or Gatekeeper blocks the download | [distribution.md](design/distribution.md), [tuner-setup.md](findings/tuner-setup.md), question 1 |
| Antivirus tools flag the unsigned executable | SmartScreen blocks the download on its first run, and a nontechnical user may stop at the warning | Sign the code before the first release | [build-tooling.md](findings/build-tooling.md#what-we-know-now) |
| Some modded civs have thin Civilopedia text | Generated notes for those civs are weaker | Overrides, and better Civilopedia entries from mod authors | [knowledge-files.md](design/knowledge-files.md#civ-notes) |
| Cost per game | Users pay their own API bills | Measure in phase 1 and publish the results. Consider a spending limit in settings | [distribution.md](design/distribution.md#decisions), [phase 1](roadmap/phase-1/README.md) |
