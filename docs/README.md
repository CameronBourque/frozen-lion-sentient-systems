# Docs map

Start here. Each folder has a README with one line per file. Open the index for the area you need, then only the files that answer your question.

| Folder or file | Answers | Changes |
| --- | --- | --- |
| [overview.md](overview.md) | What the project is, its parts, and the first milestone | Rarely |
| [rules/](rules/README.md) | How to organize and write docs, code, and commits | As conventions settle |
| [design/](design/README.md) | How each part works, and why. Each file ends with the decisions behind it | When the design changes |
| [findings/](findings/README.md) | What is true about Civ VI, FireTuner, and our tools, and how we know | After each test |
| [roadmap/](roadmap/README.md) | Phases, gates, scope, and steps | As work lands |
| [glossary.md](glossary.md) | The one name for each thing, and what it means | When a term is added or renamed |
| [risks.md](risks.md) | What could go wrong, and the fallbacks | When a risk is settled or found |

Each package also has a README that links to its design docs: [core](../packages/core/README.md), [agents](../packages/agents/README.md), [advisors](../packages/advisors/README.md).

Before you change any doc, read [rules/docs.md](rules/docs.md) and [rules/writing.md](rules/writing.md).
