# Game choices

Status: open. `SentientSystems_GetChoices` with the units, buildings, districts, wonders, and projects each city can produce, the units, buildings, and tiles each city can buy with gold, the techs and civics the player can research, the tiles from `SentientSystems_GetPlacement`, and the tech and civic trees from `SentientSystems_GetTechTree` and `SentientSystems_GetCivicTree`, the tech tree also with the Tech and Civic Shuffle mode, are confirmed in a running game. Faith purchases are confirmed in a running game. District purchases are confirmed in files only. Corps and armies are confirmed in files only.

The calls the choices use to list the legal options for each of one player's discrete choices, as the game's own screens list them. The end-turn blockers that the choices resolve are in [game-state.md](game-state.md#end-turn-blockers). See [in-game-lua.md](../design/core/in-game-lua.md).

## Questions

1. Does a unit's corps and army option read as the production panel shows it, once the Nationalism and Mobilization civics allow one? The same for buying one.
2. Does a district read as the purchase tab shows it, once Reyna with the Contractor promotion is in the city? Contractor lets a city buy districts with gold.

## What we know now

### Units

`GetData` in `Base/Assets/UI/Panels/ProductionPanel.lua`, lines 2113 to 2202, builds the panel's unit list from `GameInfo.Units()`. For each row, with `params = { UnitType = row.Hash, MilitaryFormationType = MilitaryFormationTypes.STANDARD_MILITARY_FORMATION }` and the city's `GetBuildQueue()`:

- **Listed.** The panel lists a unit when `row.MustPurchase` is false and `buildQueue:CanProduce(params, true)` returns `true`. It hides every other unit, such as one whose tech the player doesn't have. Confirmed in files and on Windows on 2026-10-26.
- **Greyed out.** A listed unit is greyed out when `buildQueue:CanProduce(params, false, true)` returns `false`. Its second value is a results table, and `results[CityCommandResults.FAILURE_REASONS]` lists the reasons. `ComposeFailureReasonStrings`, lines 1574 to 1588, passes each through `Locale.Lookup`. Each reason arrives as text in the game's language, not as a text key, so `Locale.Lookup` returns it unchanged. A reason keeps the game's icon markup, such as `[ICON_Citizen]`. Confirmed in files and on Windows on 2026-10-26.
- **Cost, progress, and turns.** `buildQueue:GetUnitCost(row.Index)`, `GetUnitProgress(row.Index)`, and `GetTurnsLeft(row.Hash)`. The panel shows progress only when it is above 0, in `ComposeProductionCostString`, lines 1589 to 1600. Turns change with the city's production, and Rome's settler went from 6 turns to 9 when the city dropped from 3 population to 1. Confirmed in files and on Windows on 2026-10-26.
- **Corps and armies.** When `results[CityOperationResults.CAN_TRAIN_CORPS]` is set, the panel also offers a corps. It checks `CanProduce` again with `MilitaryFormationTypes.CORPS_MILITARY_FORMATION`, and reads `GetUnitCorpsCost(row.Index)` and `GetTurnsLeft(row.Hash, MilitaryFormationTypes.CORPS_MILITARY_FORMATION)`. `CAN_TRAIN_ARMY` works the same way with `ARMY_MILITARY_FORMATION` and `GetUnitArmyCost`. Confirmed in files.
### Buildings

`GetData` in `ProductionPanel.lua`, lines 2020 to 2081, builds the panel's building list from `GameInfo.Buildings()`, after the districts. For each row, with the city's `GetBuildQueue()` and `GetBuildings()`:

- **Listed.** The panel lists a building when `buildQueue:CanProduce(row.Hash, true)` returns `true`, the building isn't in production, and `row.MustPurchase` is false or `cityBuildings:IsPillaged(row.Hash)` is `true`. It leaves out a building whose `row.PrereqDistrict` is the type in production, as when the district is being repaired. `CanProduce` takes the building's hash, where a unit takes a table. Confirmed in files and on Windows on 2026-10-26.
- **Greyed out.** A listed building is greyed out when `buildQueue:CanProduce(row.Hash, false, true)` returns `false`, with the reasons in `results[CityCommandResults.FAILURE_REASONS]`, as for units. Confirmed in files.
- **Cost, progress, turns, and repair.** `buildQueue:GetBuildingCost(row.Index)`, `GetBuildingProgress(row.Index)`, and `GetTurnsLeft(row.Hash)`. A building for which `IsPillaged(row.Hash)` is `true` is listed as a repair. Confirmed in files and on Windows on 2026-10-26.
- **Districts.** `PopulateDistrictsWithNestedBuildings`, lines 1029 to 1035, draws each building under the entry for its `row.PrereqDistrict`. The granary and the walls have `DISTRICT_CITY_CENTER`. Confirmed in files and on Windows on 2026-10-26.
- **Wonders.** A wonder's row has `IsWonder` set to `true`, and no `PrereqDistrict`. The panel lists it with the same checks as a building, and greys it out as [placement tiles](#placement-tiles) describes. Confirmed in files and on Windows on 2026-10-26.
- **Turns that never end.** The panel shows `999+` and `TXT_HUD_CITY_WILL_NOT_COMPLETE` when `GetTurnsLeft` returns -1, in `PopulateDistrictsWithNestedBuildings`, lines 961 to 964. Confirmed in files.

### Districts

`GetData` in `ProductionPanel.lua`, lines 1898 to 2018, builds the panel's district list from `GameInfo.Districts()`, before the buildings. For each row, with the city's `GetBuildQueue()` and `GetDistricts()`:

- **Listed.** The panel lists a district when `buildQueue:CanProduce(row.Hash, true)` returns `true` or `cityDistricts:HasDistrict(row.Index)` is `true`. It leaves out a row whose `InternalOnly` is `true`, and a one-per-city district that is in production. Confirmed in files and on Windows on 2026-10-26.
- **Built.** For a one-per-city district that the city has, that is complete, not pillaged or contaminated, and has no progress, the panel shows a checkmark in place of turns, in `PopulateDistrictsWithNestedBuildings`, line 953. Rome's panel showed **City Center** with a checkmark. Confirmed in files and on Windows on 2026-10-26.
- **Greyed out.** The panel starts from `buildQueue:CanProduce(row.Hash, false, true)`, then checks the tiles from `GetCityRelatedPlotIndexesDistrictsAlternative`. With no tile, it greys the district out unless the city has placed it already, and greys a placed one out when a reason is the text of `LOC_DISTRICT_REPAIR_LOCATION_FLOODED`. With a tile, it doesn't grey the district out when every reason equals `LOC_DISTRICT_ZONE_NO_SUITABLE_LOCATION`. That check compares the reasons with the text key, not its text. Confirmed in files.
- **Cost, progress, turns, and repair.** `buildQueue:GetDistrictCost(row.Index)`, `GetDistrictProgress(row.Index)`, and `GetTurnsLeft(row.DistrictType)`, which takes the type name. A district for which `cityDistricts:IsPillaged(row.Index)` is `true` is a repair. Confirmed in files and on Windows on 2026-10-26.

### Projects

`GetData` in `ProductionPanel.lua`, lines 2208 to 2239, builds the panel's project list from `GameInfo.Projects()`. The panel lists a project when `buildQueue:CanProduce(row.Hash, true)` returns `true`, and greys it out when `CanProduce(row.Hash, false, true)` returns `false`, with the reasons in `results[CityCommandResults.FAILURE_REASONS]`. It reads `GetProjectCost(row.Index)`, `GetProjectProgress(row.Index)`, and `GetTurnsLeft(row.ProjectType)`, and marks a project repeatable when `row.MaxPlayerInstances` isn't 1. It lists the project in production too. Campus Research Grants, `PROJECT_ENHANCE_DISTRICT_CAMPUS`, had no `MaxPlayerInstances`. Confirmed in files and on Windows on 2026-10-26.

### Purchases

The panel's purchase tabs list what a city can buy with gold and with faith. `GetData` in `ProductionPanel.lua` tries a unit or a building with gold when its `row.PurchaseYield` is `YIELD_GOLD`, at lines 2188 to 2194 and 2084 to 2090, and tries every district with gold and faith, at lines 2006 to 2016. It tries a unit or a building with faith when its `row.PurchaseYield` is `YIELD_FAITH`, or when `city:GetGold():IsUnitFaithPurchaseEnabled(row.Hash)` or `IsBuildingFaithPurchaseEnabled(row.Hash)` is `true`, at lines 2195 to 2201 and 2091 to 2097. That lets a city buy with faith some items the game marks for gold. `ComposeUnitForPurchase`, `ComposeBldgForPurchase`, and `ComposeDistrictForPurchase`, lines 1632 to 1827, each check an item the same way, with `params[CityCommandTypes.PARAM_UNIT_TYPE]`, `PARAM_BUILDING_TYPE`, or `PARAM_DISTRICT_TYPE` set to its hash, and `params[CityCommandTypes.PARAM_YIELD_TYPE]` to `GameInfo.Yields[<yield>].Index`. Confirmed in files.

- **Listed.** The panel lists the item when `CityManager.CanStartCommand(city, CityCommandTypes.PURCHASE, true, params, false)` returns `true`. Confirmed in files and on Windows on 2026-10-26.
- **Greyed out.** It greys the item out when `CanStartCommand(city, CityCommandTypes.PURCHASE, false, params, true)` returns `false`, with the reasons in `results[CityCommandResults.FAILURE_REASONS]`, or when the player's store of the yield can't afford it: `player:GetTreasury():CanAfford(cityID, hash)` for gold, and `player:GetReligion():CanAfford(cityID, hash)` for faith. The game gives no reason when the player can't afford an item, and `CanStartCommand` returns `false` with no reasons. The panel adds the text of `LOC_BUILDING_INSUFFICIENT_FUNDS`, `Not enough [ICON_Gold] Gold in treasury to purchase this.`, or for faith `LOC_BUILDING_INSUFFICIENT_FAITH`, `Not enough [ICON_Faith] Faith accumulated to purchase this.`. Confirmed in files and on Windows on 2026-10-26.
- **Cost.** `city:GetGold():GetPurchaseCost(yieldIndex, hash)`, and for a unit's corps or army, `GetPurchaseCost(yieldIndex, hash, formation)`. Confirmed in files and on Windows on 2026-10-26.
- **Corps and armies.** When the results have `CityOperationResults.CAN_TRAIN_CORPS` or `CAN_TRAIN_ARMY`, the panel checks the formation again with `params[CityCommandTypes.PARAM_MILITARY_FORMATION_TYPE]` set, and `CanAfford(cityID, hash, formation)`. Confirmed in files.

### Tile purchases

`ShowPurchases` in `Base/Assets/UI/WorldView/PlotInfo.lua`, lines 247 to 351, draws the purchase lens. The expansions don't replace the file. It asks for the tiles to buy with `CityManager.GetCommandTargets`, as [placement tiles](#placement-tiles) does, and reads each tile's gold cost with `city:GetGold():GetPlotPurchaseCost(plotIndex)`, at line 298. It disables a tile's button when the cost is more than `player:GetTreasury():GetGoldBalance()`, and shows `Locale.Lookup("LOC_PLOTINFO_YOU_NEED_MORE_GOLD_TO_PURCHASE", cost - math.floor(gold))`, such as `You need 18 more [ICON_Gold] in order to purchase this plot.`, at lines 300 to 312. Confirmed in files and on Windows on 2026-10-26.

### Techs and civics

`GetData` in `Base/Assets/UI/Choosers/ResearchChooser.lua`, lines 49 to 99, lists each row of `GameInfo.Technologies()` for which `player:GetTechs():CanResearch(index)` is `true`, and the tech in research, from `GetResearchingTech()`, which is -1 for none. The expansions' replacement, `ResearchChooser_Expansion1.lua`, only adds the research alliance icon. Confirmed in files and on Windows on 2026-10-26.

- **Cost, progress, and turns.** `GetResearchData` in `Base/Assets/UI/TechAndCivicSupport.lua`, lines 536 to 578, reads `GetResearchCost(index)`, `GetResearchProgress(index)`, and `GetTurnsToResearch(index)`. Confirmed in files and on Windows on 2026-10-26.
- **Boost.** A tech has a boost when a row of `GameInfo.Boosts()` has its `TechnologyType`. The row's `Boost` is the percent of the cost, such as 40, and `TriggerDescription` is a text key, such as the one for `Found a city on the Coast.`. `HasBoostBeenTriggered(index)` tells whether the boost fired. Confirmed in files and on Windows on 2026-10-26.
- **Recommended.** `player:GetGrandStrategicAI():GetTechRecommendations()` lists the advisor's picks, each with `TechHash`, and the chooser and the tech tree mark them with the advisor's icon. Confirmed in files and on Windows on 2026-10-26.
- **Unlocks.** `PopulateUnlockablesForTech` in `TechAndCivicSupport.lua`, lines 342 to 415, draws an icon for each row of `GetUnlockablesForTech(techType, playerID, items)`, from `Base/Assets/UI/TechAndCivicUnlockables.lua`, whose first field is the type, such as `UNIT_GALLEY`. `items` is `GetFilteredUnlockableItems(playerID)`, which is slow to build, so the caller builds it once. `include("TechAndCivicUnlockables")` loads the file in `SentientSystemsCore_UI`. The function then draws a star, a special unlock, with the tech's `Description` as its tooltip, at lines 391 to 412. Confirmed in files and on Windows on 2026-10-26.
- **Civics.** `GetData` in `Base/Assets/UI/Choosers/CivicsChooser.lua`, lines 45 to 96, and `GetCivicData` in `TechAndCivicSupport.lua`, lines 653 to 695, work as for techs, with `GameInfo.Civics()` and `player:GetCulture()`: `CanProgress(index)`, `GetProgressingCivic()`, `GetCultureCost(index)`, `GetCulturalProgress(index)`, `GetTurnsToProgressCivic(index)`, and `HasBoostBeenTriggered(index)`. A civic's boost is the row of `GameInfo.Boosts()` with its `CivicType`. The advisor's picks come from `GetCivicsRecommendations()`, each with `CivicHash`. `GetUnlockablesForCivic(civicType, playerID)` lists the unlocks, such as `POLICY_AGOGE` and `UNIT_TRADER`, and takes no list of items. `PopulateUnlockablesForCivic`, lines 233 to 336, draws a government as a card with its policy slots, and leaves out the civic's star when it shows an icon for an envoy or a governor title. Confirmed in files and on Windows on 2026-10-26.

### Tech and civic trees

`Base/Assets/UI/Screens/TechTree.lua` draws the tech tree. `DLC/Expansion1` adds the research alliance icon, and `DLC/Expansion2` only changes the search. Confirmed in files.

- **Nodes.** `PopulateItemData`, lines 1374 to 1447, builds the nodes from `UITree.GetAvailableTechs()`, which works in `SentientSystemsCore_UI`. Each node has `Name`, the tech's type, `Cost`, `TreeRow`, and `PrereqTechTypes`, the prerequisites the running game has. In a game with the Tech and Civic Shuffle mode, they were the shuffled ones, such as `TECH_SAILING` after `TECH_ANIMAL_HUSBANDRY`. `Cost` is the base cost, 25 for Pottery, where `GetResearchCost` gave the player's cost, 12. Confirmed in files and on Windows on 2026-10-26.
- **Status and turns.** `GetCurrentData`, lines 1059 to 1255, gives each node a status: researched when `HasTech(index)` is `true`, current for the tech in research, ready when `CanResearch(index)` is `true`, and blocked otherwise. The node in research shows `GetTurnsLeft()`, and the others `GetTurnsToResearch(index)`. `PopulateNode`, lines 778 to 967, shows turns only when they are above 0, and no boost for a researched node. Before the first city, every node's turns were -1. Confirmed in files and on Windows on 2026-10-26.
- **Unrevealed nodes.** With the Tech and Civic Shuffle mode, `IsTechRevealed(index)` is `false` for a node the player can't see yet. `PopulateNode` shows such a node as `LOC_TECH_TREE_NOT_REVEALED_TECH`, `Unrevealed`, with no unlocks or boost. Its lines to other nodes still show. On turn 1, 3 of the 77 nodes were revealed: Animal Husbandry, Mining, and Pottery. Without the mode, `IsTechRevealed` returned `true` for every node. Confirmed in files and on Windows on 2026-10-26.
- **Civic tree.** `Base/Assets/UI/Screens/CivicsTree.lua` builds the civic tree the same way, from `UITree.GetAvailableCivics()`, with `HasCivic(index)`, `GetTurnsLeft()`, and `IsCivicRevealed(index)` on `player:GetCulture()`, in `GetCurrentData`, lines 1231 to 1432. A civic node holds its type in `CivicName` and its index in `CivicType`, and `PrereqCivicTypes` lists types, as `PopulateItemData`, lines 1566 to 1645, reads them. The screen also draws an icon with a number for each envoy or governor title a civic gives, which the civic's row doesn't hold. Confirmed in files and on Windows on 2026-10-26.
- **Timeline.** `GetCurrentData` in `TechTree.lua`, lines 1143 to 1177, reads each major player from `Game.GetPlayers({ Major = true })`, and marks a player the local player has met, with `player:GetDiplomacy():HasMet(id)`, at the column of the latest tech they have researched. `HasMet` returned `false` for the player's own ID. Confirmed in files and on Windows on 2026-10-26.

### Placement tiles

`Base/Assets/UI/AdjacencyBonusSupport.lua` finds the tiles where a district or a wonder can go. The expansions don't replace it. Confirmed in files.

- **Tiles the city owns.** `CityManager.GetOperationTargets(city, CityOperationTypes.BUILD, params)`, with `params[CityOperationTypes.PARAM_DISTRICT_TYPE]` set to a district's hash, or `params[CityOperationTypes.PARAM_BUILDING_TYPE]` to a wonder's, returns plot indexes in `results[CityOperationResults.PLOTS]`. Confirmed in files and on Windows on 2026-10-26.
- **Tiles to buy.** `CityManager.GetCommandTargets(city, CityCommandTypes.PURCHASE, params)`, with `params[CityCommandTypes.PARAM_PLOT_PURCHASE]` set to `UI.GetInterfaceModeParameter(CityCommandTypes.PARAM_PLOT_PURCHASE)`, returns the plot indexes the city could buy in `results[CityCommandResults.PLOTS]`. `plot:CanHaveDistrict(districtIndex, owner, cityID)` and `plot:CanHaveWonder(buildingIndex, owner, cityID)` check each one. Both work in `SentientSystemsCore_UI`. Rome had 17 tiles to buy. Confirmed in files and on Windows on 2026-10-26.
- **Tiles to buy that the panel counts.** For a district, `IsShownIfPlotPurchaseable`, lines 155 to 169, keeps a tile to buy only when the district gets an adjacency bonus on it, or when the district has no adjacency bonuses. For a wonder, it keeps every tile that `CanHaveWonder` allows. Confirmed in files.
- **Adjacency.** `plot:GetAdjacencyYield(playerID, cityID, districtIndex, yieldIndex)` returns a district's bonus on a tile for one yield. `GetAdjacentYieldBonusString`, lines 177 to 247, reads it for each yield. Confirmed in files and on Windows on 2026-10-26.
- **Wonders with no tile the city owns.** When `CanProduce` refuses a wonder with `results[CityOperationResults.NO_SUITABLE_LOCATION]` set to `true`, the panel doesn't grey it out if it has a tile to buy, in `GetData`, lines 2041 to 2047. The Pyramids, the Great Bath, and Stonehenge each had no tile in Rome's territory and one tile to buy, and Rome's panel showed the Pyramids and the Great Bath in the same style as the buildings. Confirmed in files and on Windows on 2026-10-26.

## Method

1. In `SentientSystemsCore_UI`, loop over `GameInfo.Units()` and `GameInfo.Buildings()` for each city with the checks above, and compare the lists with the production panel.
2. To change the player's gold, in `GameCore_Tuner`, send `Players[0]:GetTreasury():ChangeGoldBalance(<amount>)`, and the opposite amount afterwards.
3. To unlock buildings and districts in an early game, in `GameCore_Tuner`, send `Players[0]:GetTechs():SetTech(GameInfo.Technologies["TECH_POTTERY"].Index, true)`, and the same for `TECH_MASONRY`, `TECH_WRITING`, and `TECH_ASTROLOGY`. To add a district without producing it, in `GameCore_Tuner`, send `WorldBuilder.CityManager():CreateDistrict(city, GameInfo.Districts["DISTRICT_CAMPUS"].Index, 100, Map.GetPlot(x, y):GetIndex())`, as `DLC/BlackDeathScenario` does. To remove one, send `WorldBuilder.CityManager():RemoveDistrict(city:GetDistricts():GetDistrict(<district index>))`. In `GameCore_Tuner`, a city's `GetDistricts()` has no `Members()`. To add a building, send `WorldBuilder.CityManager():CreateBuilding(city, "BUILDING_SHRINE", 100, plotIndex)`. Reload the save afterwards to undo them.
4. To see faith purchases, in `GameCore_Tuner`, add a holy site with a shrine as in step 3, send `Players[0]:GetReligion():ChangeFaithBalance(600)`, and send `Game.GetGreatPeople():CreatePerson(0, GameInfo.GreatPersonIndividuals["GREAT_PERSON_INDIVIDUAL_SIDDHARTHA_GAUTAMA"].Hash, x, y)` for a Great Prophet. Faith added during a turn doesn't allow a pantheon until the next turn: `GetReligion():CanCreatePantheon()` returned `false` with 600 faith. End the turn, pick a pantheon, then found a religion with the prophet.
5. To see a greyed-out unit, in `GameCore_Tuner`, send `Players[0]:GetCities():FindID(<cityID>):ChangePopulation(-2)` to a city with 3 population, so the settler needs more population. Send `ChangePopulation(2)` afterwards.
6. To test a choices file that the `.modinfo` doesn't list yet, without a restart, send the file's code without its comments and `include` lines to `SentientSystemsCore_UI`, then the choices file's code the same way. Windows limits a command line to 8,191 characters, so pass long code to the sending script in a file.
7. Read `SentientSystems_GetChoices(Game.GetLocalPlayer())` with `npm run state`, which prints it after the state.
